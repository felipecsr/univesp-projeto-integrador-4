# Modo de Trabalho

## Princípios

- O Kanban no Google Drive organiza as tarefas.
- O GitHub registra código, notebooks e documentação técnica.
- A branch `main` representa a versão validada do projeto.
- Alterações destinadas à `main` devem ser feitas por Pull Request.
- Cada integrante pode escolher seu ambiente de trabalho, desde que a entrega final seja incorporada ao repositório de forma organizada.
- Dados brutos ou arquivos grandes permanecem fora do GitHub.

## Fluxo de uma tarefa

1. Selecionar uma tarefa do Kanban.
2. Executar e validar a entrega.
3. Atualizar código e/ou documentação no GitHub.
4. Abrir Pull Request quando houver alteração destinada à `main`.
5. Após revisão e merge, atualizar a tarefa como concluída no Kanban.

## Convenções iniciais

- Commits devem descrever objetivamente a alteração realizada.
- Branches de trabalho podem usar prefixos como `feature/`, `fix/` ou `docs/`.
- Mudanças relevantes de metodologia ou arquitetura devem ser registradas na documentação.
- Bloqueios devem ser sinalizados no Kanban e comunicados ao grupo.
